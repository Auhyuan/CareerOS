# 就业指导 AI 平台方案 v3.0

> 核心定位：岗位画像驱动的 AI 能力闯关平台
> 核心目标：让用户画像的能力等级逐步达到岗位画像的目标等级，从而提升岗位匹配度。

---

## 一、产品一句话定位

本平台不是传统学习平台，也不是普通 AI 简历优化工具，而是一个围绕目标岗位画像设计的 **AI 能力测评与闯关成长平台**。

用户选择目标岗位后，平台会根据岗位画像定义目标能力等级，再通过简历解析、用户画像生成、分级关卡测评、AI 单题批改、错因分析、补强训练和等级升级，帮助用户逐步达到目标岗位要求。

---

## 二、核心理念

### 2.1 岗位画像定义目标等级

岗位画像不是普通岗位介绍，而是这个岗位需要的能力标准。

例如：

```text
目标岗位：AI 应用开发工程师

RAG：目标 5 级
LangGraph：目标 4 级
FastAPI：目标 4 级
Milvus：目标 3 级
Docker：目标 3 级
PostgreSQL：目标 3 级
```

岗位画像回答的问题是：

> 想胜任这个岗位，需要掌握哪些技能？每个技能需要达到什么等级？

---

### 2.2 用户画像定义当前等级

用户上传简历后，Agent 会解析用户的教育背景、项目经历、技能描述、工作经验，生成用户初始画像。

例如：

```text
用户当前画像：

RAG：2 级
LangGraph：1 级
FastAPI：3 级
Milvus：0 级
Docker：2 级
PostgreSQL：2 级
```

用户画像回答的问题是：

> 用户现在已经具备什么能力？每个技能大概处于什么等级？

---

### 2.3 平台任务是让用户画像追上岗位画像

平台的核心任务不是推荐课程，而是：

```text
当前等级 → 目标等级
```

例如：

```text
RAG：2 → 5
LangGraph：1 → 4
FastAPI：3 → 4
Milvus：0 → 3
```

也就是说，平台要做的是帮助用户一关一关通过能力考核，把用户画像里的技能等级逐步提升到岗位画像要求的等级。

---

## 三、产品核心模型

### 3.1 四个核心对象

```text
岗位画像：定义目标岗位要求
用户画像：定义用户当前能力
能力关卡：验证用户是否达到下一等级
匹配度：衡量用户画像与岗位画像的接近程度
```

---

## 四、整体业务闭环

```text
用户选择 / 创建岗位画像
        ↓
用户上传简历
        ↓
Agent 生成用户画像
        ↓
系统对比岗位画像和用户画像
        ↓
生成岗位匹配度与能力差距
        ↓
系统生成技能闯关路径
        ↓
用户逐题作答
        ↓
Agent 单题批改与讲解
        ↓
用户通过一个个关卡
        ↓
全部关卡通过后，技能等级升级
        ↓
用户画像更新
        ↓
岗位匹配度重新计算
        ↓
继续挑战下一等级
```

---

## 五、能力等级体系

平台统一采用 0～5 级能力等级。

| 等级 | 名称    | 说明                  |
| -- | ----- | ------------------- |
| 0  | 未接触   | 没听过，或只听过名字          |
| 1  | 概念了解  | 知道是什么，但没有实践         |
| 2  | 入门实践  | 跑过 Demo，能照着文档完成基础功能 |
| 3  | 项目使用  | 在真实项目中使用过，能解决常见问题   |
| 4  | 独立落地  | 能独立设计方案，处理复杂场景      |
| 5  | 平台化能力 | 能做平台封装、架构优化、指导他人    |

## 六、岗位画像设计

### 6.1 岗位画像类型

平台中有三类岗位画像：

```text
1. 平台预设岗位画像
2. 用户私有岗位画像
3. 用户共享岗位画像
```

---

### 6.2 平台预设岗位画像

平台预设画像由平台维护，可以定期更新。

例如：

```text
AI 应用开发工程师
Java 后端开发工程师
前端开发工程师
Python 后端开发工程师
数据分析师
测试开发工程师
```

平台预设岗位画像的作用是给用户一个标准参考。

---

### 6.3 用户私有岗位画像

用户可以基于平台预设岗位画像创建自己的岗位画像，也可以通过上传 JD 或描述目标生成。

例如用户可以说：

```text
我想找 AI 应用开发岗位，偏后端 AI，不想做算法训练。
岗位最好要求 FastAPI、RAG、LangGraph、Milvus、MCP。
```

Agent 会生成用户自己的岗位画像。

---

### 6.4 岗位画像定期更新

平台预设岗位画像可以定期根据市场变化更新。

更新方式：

```text
采集岗位 JD
    ↓
清洗垃圾信息
    ↓
Agent 总结岗位能力变化
    ↓
生成新版岗位画像
    ↓
与旧版画像做差异对比
    ↓
人工或规则审核
    ↓
发布新版本
```

平台画像更新后，不强制修改用户私有画像，而是提醒用户是否同步。

---

## 七、用户画像设计

### 7.1 用户画像来源

用户画像来自多个来源：

```text
1. 简历解析
2. 用户自评
3. Agent 追问
4. 做题结果
5. 关卡通过记录
6. 项目任务提交结果
```

早期用户画像可以根据简历生成，但后续画像升级必须依赖闯关结果。

---

### 7.2 用户画像示例

```json
{
  "user_id": "user_001",
  "target_job": "AI 应用开发工程师",
  "skills": [
    {
      "name": "RAG",
      "current_level": 2,
      "evidence": ["简历中提到知识库项目", "有基础向量检索经验"]
    },
    {
      "name": "LangGraph",
      "current_level": 1,
      "evidence": ["简历中提到 Agent，但缺少复杂工作流证据"]
    },
    {
      "name": "FastAPI",
      "current_level": 3,
      "evidence": ["项目中使用 FastAPI 开发后端接口"]
    }
  ]
}
```

## 八、差距分析设计

系统对比岗位画像和用户画像，生成能力差距。

例如：

```text
目标岗位：AI 应用开发工程师

RAG：当前 2 / 目标 5，差 3 级
LangGraph：当前 1 / 目标 4，差 3 级
FastAPI：当前 3 / 目标 4，差 1 级
Milvus：当前 0 / 目标 3，差 3 级
Docker：当前 2 / 目标 3，差 1 级
```

差距不只是展示给用户看，还会直接生成闯关路径。

---

## 九、能力闯关系统

### 9.1 闯关系统定位

平台不以“看资料”作为主流程，而是以“做题闯关”作为主流程。

用户通过题目快速发现自己的不足，Agent 通过用户答案快速捕获真实短板。

---

### 9.2 关卡设计

每个技能的每一级升级，都对应一组关卡。

例如：

```text
RAG 2 → 3 升级关卡

第 1 关：RAG 基础流程理解
第 2 关：Chunk / Embedding / Retriever 理解
第 3 关：检索失败场景分析
第 4 关：引用来源与上下文组织
第 5 关：小项目实现题
```

规则：

```text
全部关键关卡通过 → 技能等级升级
任意关键关卡失败 → 暂不升级，进入补强
```

---

### 9.3 闯关示例

用户当前：

```text
RAG：2 级
```

目标岗位要求：

```text
RAG：5 级
```

系统生成：

```text
当前挑战：RAG 2 → 3

第 1 关：RAG 流程理解
第 2 关：文本切片策略
第 3 关：向量检索基础
第 4 关：检索失败排查
第 5 关：小型知识库问答任务
```

用户通过全部关卡后：

```text
RAG：2 → 3
岗位匹配度：58% → 66%
下一目标：RAG 3 → 4
```

## 十、批改机制设计

### 10.1 核心原则

平台不采用“整套题一次性批改”的模式。

推荐采用：

```text
单题即时批改 + 模块阶段总结 + 技能等级升级
```

---

### 10.2 单题即时批改

用户每做一道题，Agent 立即批改。

单题批改内容包括：

```text
1. 是否正确
2. 错在哪里
3. 哪些地方不够准确
4. 正确答案或参考思路
5. 暴露了哪个知识点短板
6. 是否需要生成补强题
```

这样用户可以马上知道自己哪里不懂。

---

### 10.3 模块阶段总结

一组相关题目完成后，Agent 输出模块总结。

例如：

```text
模块：RAG 检索质量

完成题目：5 道
通过题目：3 道
未通过题目：2 道

主要短板：
1. chunk_size 对召回质量的影响理解不足
2. 没有区分向量召回和 rerank
3. 对相似度阈值的作用理解不清

模块结论：
暂不通过，需要完成补强题后重新挑战。
```

---

### 10.4 技能等级升级

只有当前等级到下一等级的所有关键关卡都通过，才允许升级用户画像。

例如：

```text
Python 2 → 3

关卡 1：基础语法，通过
关卡 2：数据结构，通过
关卡 3：函数与异常，通过
关卡 4：代码实现，通过
关卡 5：项目场景，通过

结果：
Python 2 → 3
```

如果某一关失败：

```text
Python 仍为 2 级
失败关卡：异常处理
系统生成异常处理补强题
```

---

## 十一、画像升级规则

### 11.1 硬性升级条件

用户画像升级必须满足：

```text
当前等级 → 下一等级的所有必过关卡全部通过
```

不能只根据总分升级。

不能因为用户答对一道题就升级。

不能因为用户自评会了就升级。

---

### 11.2 升级依据

每次技能等级升级，都要有证据链。

例如：

```json
{
  "skill": "RAG",
  "old_level": 2,
  "new_level": 3,
  "reason": "用户通过了 RAG 2→3 的全部关键关卡",
  "evidence": [
    "RAG 流程理解题通过",
    "文本切片策略题通过",
    "向量检索题通过",
    "检索失败排查题通过",
    "小型知识库问答任务通过"
  ],
  "match_score_change": {
    "before": 58,
    "after": 66
  }
}
```

---

### 11.3 未通过处理

如果用户没有通过某一关，系统不升级画像，而是生成补强任务。

例如：

```text
你没有通过「检索失败排查」这一关。

主要问题：
1. 没有提到 chunk 粒度
2. 没有分析召回数量
3. 没有区分召回失败和生成幻觉

补强任务：
1. 完成 3 道检索失败排查题
2. 重新挑战当前关卡
```

---

## 十二、题目体系设计

### 12.1 题目类型

平台题目不应该只有选择题，而应该包含多种类型：

| 题型  | 作用         |
| --- | ---------- |
| 选择题 | 检查基础概念     |
| 判断题 | 检查易混点      |
| 简答题 | 检查理解深度     |
| 场景题 | 检查真实业务分析能力 |
| 代码题 | 检查实现能力     |
| 项目题 | 检查岗位级实践能力  |

---

### 12.2 题目结构

每一道题都应该绑定技能、等级、模块和岗位画像。

```json
{
  "question_id": "q_001",
  "skill": "RAG",
  "from_level": 2,
  "to_level": 3,
  "module": "检索质量",
  "knowledge_point": "chunk_size 对召回质量的影响",
  "question_type": "场景题",
  "question": "用户反馈知识库经常答非所问，你会从哪些方面排查？",
  "pass_criteria": [
    "能提到文档质量",
    "能提到 chunk 策略",
    "能提到 embedding 模型",
    "能提到召回数量和相似度阈值",
    "能区分检索失败和生成幻觉"
  ],
  "is_required": true
}
```

## 十三、Agent 体系设计

### 13.1 岗位画像 Agent

负责：

```text
1. 生成平台预设岗位画像
2. 根据用户上传 JD 生成私有岗位画像
3. 对比新旧画像变化
4. 过滤垃圾岗位要求
5. 判断技能重要性和目标等级
```

---

### 13.2 简历解析 Agent

负责：

```text
1. 解析用户简历
2. 提取技能、项目、经验、学历
3. 生成初始用户画像
4. 判断简历中的能力证据
5. 标记表达不清楚的地方
```

---

### 13.3 匹配分析 Agent

负责：

```text
1. 对比岗位画像和用户画像
2. 计算岗位匹配度
3. 找出技能差距
4. 判断短板优先级
5. 生成闯关路径
```

---

### 13.4 出题 Agent

负责：

```text
1. 根据技能等级生成关卡题
2. 控制题目难度
3. 生成必过题和加分题
4. 生成不同题型
5. 避免题目太泛
```

---

### 13.5 批改 Agent

负责：

```text
1. 单题即时批改
2. 判断答案是否达标
3. 标注错误点
4. 给出正确思路
5. 识别知识点短板
6. 生成补强题
```

---

### 13.6 升级判定 Agent

负责：

```text
1. 汇总关卡通过情况
2. 判断是否满足升级条件
3. 生成升级证据链
4. 更新用户画像
5. 重新计算岗位匹配度
```

## 十五、MVP 版本建议

### 15.1 MVP 不做什么

第一版不要做太重。

暂时不做：

```text
1. 大规模岗位爬虫
2. 完整课程系统
3. 学习资料库
4. 视频学习
5. 岗位画像广场
6. 社区功能
7. 付费课程合作
```

---

### 15.2 MVP 必做什么

第一版重点跑通核心闭环：

```text
岗位画像
    ↓
用户画像
    ↓
匹配度
    ↓
能力差距
    ↓
闯关题
    ↓
单题批改
    ↓
关卡通过
    ↓
画像升级
    ↓
匹配度提升
```

---

### 15.3 MVP 首批岗位

建议先做 3～5 个岗位：

```text
1. AI 应用开发工程师
2. Java 后端开发工程师
3. 前端开发工程师
4. Python 后端开发工程师
5. 数据分析师
```

早期最好先重点做一个岗位，比如：

```text
AI 应用开发工程师
```

因为这个岗位和你的能力最匹配，也最容易设计题目和画像。

---

### 15.4 MVP 首批技能

以 AI 应用开发工程师为例，首批技能可以是：

```text
Python
FastAPI
RAG
LangGraph
Milvus / 向量数据库
PostgreSQL
Docker
Git
```

---

### 15.5 MVP 首批关卡

不要一开始做 0～5 全等级。

可以先做：

```text
RAG 1 → 2
RAG 2 → 3

LangGraph 0 → 1
LangGraph 1 → 2

FastAPI 2 → 3
FastAPI 3 → 4

Milvus 0 → 1
Milvus 1 → 2
```

先验证用户是否愿意闯关、是否认可批改结果、是否愿意为了提升匹配度继续做题。

## 十七、产品差异化

### 17.1 和 AI 简历工具的区别

普通 AI 简历工具主要是帮用户改文本。

本平台不是先改简历，而是先判断用户离目标岗位差什么，再通过关卡验证用户是否真的具备能力。

---

### 17.2 和学习平台的区别

普通学习平台是：

```text
看课 → 做题 → 完成课程
```

本平台是：

```text
岗位画像 → 能力差距 → 闯关题 → AI 批改 → 画像升级 → 匹配度提升
```

---

### 17.3 和刷题平台的区别

普通刷题平台只告诉用户对错。

本平台会进一步：

```text
1. 分析错因
2. 定位能力短板
3. 生成补强题
4. 判断是否升级用户画像
5. 重新计算岗位匹配度
```

---

## 十八、最终产品表达

可以这样对外描述：

> 这是一个岗位画像驱动的 AI 能力闯关平台。用户选择目标岗位后，平台会根据简历生成用户画像，识别用户与岗位要求之间的能力差距，并通过一关一关的 AI 出题、单题批改、错因分析和补强训练，帮助用户逐步提升技能等级。只有通过对应等级的全部关键关卡，用户画像才会升级，岗位匹配度也会随之提升。

更短的表达：

> 不是告诉你该学什么，而是通过一道道岗位能力关卡，帮你证明自己达到了目标岗位要求。

---

## 十九、核心总结

平台最终闭环是：

```text
岗位画像定义目标
用户画像定义现状
能力差距生成关卡
用户逐题闯关
Agent 即时批改
失败则补强
全部过关则升级画像
画像升级后提升匹配度
最终达到岗位要求
```

这套方案的核心竞争力在于：

```text
1. 目标明确：所有题目都服务于目标岗位画像
2. 过程可验证：不是学了就算，而是过关才算
3. 反馈及时：每道题都有 AI 批改和讲解
4. 成长可量化：用户画像等级持续提升
5. 求职强相关：匹配度随能力提升动态变化
```
