# 就业指导 AI 平台方案 v3.0

> 核心定位：岗位画像驱动的 AI 能力闯关平台
> 核心目标：让用户画像的能力等级逐步达到岗位画像的目标等级，从而提升岗位匹配度。

---

## 一、产品一句话定位

本平台不是传统学习平台，也不是普通 AI 简历优化工具，而是一个围绕目标岗位画像设计的 **AI 能力测评与闯关成长平台**。

用户选择目标岗位后，平台会根据岗位画像定义目标能力等级，再通过简历解析、用户画像生成、分级关卡测评、AI 单题批改、错因分析、补强训练和等级升级，帮助用户逐步达到目标岗位要求。

---

## 二、核心理念

### 2.1 岗位画像定义目标等级

岗位画像不是普通岗位介绍，而是这个岗位需要的能力标准。

例如：

```text
目标岗位：AI 应用开发工程师

RAG：目标 5 级
LangGraph：目标 4 级
FastAPI：目标 4 级
Milvus：目标 3 级
Docker：目标 3 级
PostgreSQL：目标 3 级
```

岗位画像回答的问题是：

> 想胜任这个岗位，需要掌握哪些技能？每个技能需要达到什么等级？

---

### 2.2 用户画像定义当前等级

用户上传简历后，Agent 会解析用户的教育背景、项目经历、技能描述、工作经验，生成用户初始画像。

例如：

```text
用户当前画像：

RAG：2 级
LangGraph：1 级
FastAPI：3 级
Milvus：0 级
Docker：2 级
PostgreSQL：2 级
```

用户画像回答的问题是：

> 用户现在已经具备什么能力？每个技能大概处于什么等级？

---

### 2.3 平台任务是让用户画像追上岗位画像

平台的核心任务不是推荐课程，而是：

```text
当前等级 → 目标等级
```

例如：

```text
RAG：2 → 5
LangGraph：1 → 4
FastAPI：3 → 4
Milvus：0 → 3
```

也就是说，平台要做的是帮助用户一关一关通过能力考核，把用户画像里的技能等级逐步提升到岗位画像要求的等级。

---

## 三、产品核心模型

### 3.1 四个核心对象

```text
岗位画像：定义目标岗位要求
用户画像：定义用户当前能力
能力关卡：验证用户是否达到下一等级
匹配度：衡量用户画像与岗位画像的接近程度
```

---

## 四、整体业务闭环

~~~
用户选择 / 创建岗位画像
        ↓
用户上传简历或补充个人材料
        ↓
简历解析 Agent 生成简历画像与初始技能证据
        ↓
Agent 与用户交互，校准技能掌握情况
        ↓
生成初始用户能力画像
        ↓
系统对比岗位画像和用户能力画像，计算匹配度与能力差距
        ↓
所有未达到岗位要求的技能进入评估队列
        ↓
针对当前等级到下一等级生成主观面试题
        ↓
用户逐题作答，Agent 单题评分、追问或生成同类补强题
        ↓
一个技能的五个必过能力单元全部达到 60 分
        ↓
技能等级升级，更新用户能力画像和岗位匹配度
        ↓
继续处理仍未达标的技能，直到全部岗位能力达标
~~~

## 五、能力等级体系

平台统一采用 0～5 级能力等级。

| 等级 | 名称    | 说明                  |
| -- | ----- | ------------------- |
| 0  | 未接触   | 没听过，或只听过名字          |
| 1  | 概念了解  | 知道是什么，但没有实践         |
| 2  | 入门实践  | 跑过 Demo，能照着文档完成基础功能 |
| 3  | 项目使用  | 在真实项目中使用过，能解决常见问题   |
| 4  | 独立落地  | 能独立设计方案，处理复杂场景      |
| 5  | 平台化能力 | 能做平台封装、架构优化、指导他人    |

## 六、岗位画像设计

### 6.1 岗位画像类型

平台中有三类岗位画像：

```text
1. 平台预设岗位画像
2. 用户私有岗位画像
3. 用户共享岗位画像
```

---

### 6.2 平台预设岗位画像

平台预设画像由平台维护，可以定期更新。

例如：

```text
AI 应用开发工程师
Java 后端开发工程师
前端开发工程师
Python 后端开发工程师
数据分析师
测试开发工程师
```

平台预设岗位画像的作用是给用户一个标准参考。

---

### 6.3 用户私有岗位画像

用户可以基于平台预设岗位画像创建自己的岗位画像，也可以通过上传 JD 或描述目标生成。

例如用户可以说：

```text
我想找 AI 应用开发岗位，偏后端 AI，不想做算法训练。
岗位最好要求 FastAPI、RAG、LangGraph、Milvus、MCP。
```

Agent 会生成用户自己的岗位画像。

---

### 6.4 岗位画像定期更新

平台预设岗位画像可以定期根据市场变化更新。

更新方式：

```text
采集岗位 JD
    ↓
清洗垃圾信息
    ↓
Agent 总结岗位能力变化
    ↓
生成新版岗位画像
    ↓
与旧版画像做差异对比
    ↓
人工或规则审核
    ↓
发布新版本
```

平台画像更新后，不强制修改用户私有画像，而是提醒用户是否同步。

---

## 七、用户画像设计

### 7.1 三层画像

平台应区分三层信息：

~~~
简历画像：用户在简历、附件和自述中表达过什么
岗位画像：目标岗位要求用户达到什么能力
用户能力画像：平台当前能够验证用户具备什么能力
~~~

简历画像只提供初始证据，不能直接代表真实能力。用户能力画像由简历解析、Agent 追问、主观题回答、单题评分、补强结果和技能升级记录共同形成。

### 7.2 用户能力画像

每项技能至少包含：

~~~
skill_id
当前等级
岗位目标等级
等级状态：estimated / verified
能力证据
更新时间
~~~

estimated 表示根据简历、用户自述和 Agent 交互得出的初始判断；verified 表示用户已经通过对应等级的能力评估。

## 八、差距分析设计

系统逐项对比岗位目标等级和用户当前等级：

~~~
Python：当前 2 / 目标 4，进入 Python 2→3 评估
RAG：当前 1 / 目标 4，进入 RAG 1→2 评估
FastAPI：当前 3 / 目标 3，已达标，不重复考察
Docker：当前 2 / 目标 3，进入 Docker 2→3 评估
~~~

规则：

~~~
当前等级 >= 目标等级：技能已达标。
当前等级 < 目标等级：技能必须进入评估队列。
每次只评估当前等级到下一等级，不允许跳级。
升级后重新计算差距；仍未达标则继续下一阶段评估。
~~~

平台不是只挑选差距最大的技能，而是逐项处理所有未达到目标岗位要求的技能。

## 九、能力闯关系统

### 9.1 核心定位

平台不使用固定刷题作为主流程，而是使用与目标岗位相关的主观面试题，验证用户是否真正具备下一等级能力。

### 9.2 五个能力单元

每个技能从当前等级升级到下一等级时，必须设置五个必过能力单元。五个单元应覆盖不同能力方向，不能用五道相似题重复考察同一件事。

例如 Python 2→3：

~~~
1. 语言基础与数据结构
2. 函数、模块与代码组织
3. 异常处理与问题排查
4. 实际编码与工程实践
5. 项目场景分析
~~~

每个单元先生成一道与岗位场景相关的主观面试题。

### 9.3 自适应补强

~~~
单元得分 >= 60：该单元通过。
单元得分 < 60：该单元未通过。
~~~

未通过时，Agent 根据用户回答进行关键点追问，或生成同能力方向的场景新题。追问和新题仍属于原能力单元，直到该单元获得有效通过结果。

## 十、批改机制设计

### 10.1 单题即时评估

用户每回答一道主观题，Agent 立即输出：

~~~
得分（0～100）
是否达到 60 分通过线
回答正确的部分
缺失、错误或不够准确的部分
参考思路
暴露的知识点短板
下一步：通过、追问或同类补强题
~~~

### 10.2 评分原则

评分必须基于题目的能力目标与通过标准，不能只根据回答长度或表达流畅度判断。

| 维度 | 说明 |
| --- | --- |
| 正确性 | 技术结论是否正确 |
| 完整性 | 是否覆盖关键判断点 |
| 场景分析 | 是否能够结合真实岗位或工程场景 |
| 实践可行性 | 方案是否能实际落地 |
| 表达清晰度 | 是否能够清楚说明思路 |

### 10.3 五单元规则

五个能力单元必须全部通过。即使平均分超过 60，只要任意一个单元未通过，技能仍不能升级。

## 十一、画像升级规则

### 11.1 升级条件

某项技能从当前等级升级到下一等级，必须满足：

~~~
五个必过能力单元全部通过
每个单元最终有效得分均不低于 60 分
~~~

不能仅依据总分、单题结果、用户自评或简历描述升级。

### 11.2 升级证据链

每次升级必须记录技能、旧等级与新等级、五个能力单元的最终得分、每个单元的尝试次数、评分依据和升级时间。

升级后更新用户能力画像并重新计算岗位匹配度。

## 十二、题目体系设计

### 12.1 MVP 题目定位

MVP 的核心题型是主观面试题，选择题、判断题和代码题可以后续作为辅助训练，但不作为技能升级的唯一依据。

每道题必须绑定：

~~~
目标岗位画像
技能
当前等级
目标等级
能力单元
岗位场景
通过标准
~~~

题目由岗位画像、用户能力画像和当前等级差距共同决定，因此不是泛化技术题，而是面向目标岗位的能力验证题。

## 十三、Agent 体系设计

### 13.1 岗位画像 Agent

负责生成岗位画像、提炼岗位技能与目标等级。

### 13.2 简历解析与交互校准 Agent

负责解析简历和附件，提取初始技能证据；对证据不足或表达不清楚的技能与用户交互，生成初始用户能力画像。

### 13.3 匹配分析 Agent

负责计算岗位匹配度，找出全部未达标技能，并为每项未达标技能生成逐级评估队列。

### 13.4 主观题生成 Agent

负责根据岗位场景、技能差距和目标等级生成五个能力单元的主观面试题；用户低分后生成追问或同类补强题。

### 13.5 单题评估 Agent

负责对用户主观回答进行 0～100 分评分，输出错因、参考思路和下一步评估动作。

### 13.6 技能升级判定 Agent

负责汇总五个能力单元的有效结果，记录升级证据链，更新用户能力画像，并触发匹配度重新计算。

## 十四、核心页面设计

### 14.1 岗位画像页

展示岗位名称、目标技能等级、核心技能、加分技能、画像版本和复制入口。

### 14.2 用户能力画像页

展示用户当前技能等级与岗位目标等级、技能证据来源、等级状态、五个能力单元完成情况、等级升级历史和岗位匹配度变化。

### 14.3 匹配度报告页

展示目标岗位、当前匹配度、所有未达标技能、每项技能当前等级与目标等级、当前评估队列和预计提升空间。

### 14.4 主观能力评估页

展示当前技能及升级阶段、当前能力单元、主观面试题与作答区域、Agent 评分、错因、追问或同类补强题，以及五个能力单元进度。

### 14.5 技能升级结果页

展示当前升级阶段是否通过、五个单元的最终得分、主要短板、用户画像变化和岗位匹配度变化。

## 十五、MVP 版本建议

### 15.1 MVP 必做闭环

~~~

    ↓
简历画像
    ↓
Agent 交互校准
    ↓
用户能力画像
    ↓
岗位匹配度与全部未达标技能
    ↓
每项技能的五个主观能力单元

    ↓

### 15.2 MVP 首批岗位

先聚焦 AI 应用开发工程师，验证闭环后再扩展 Java 后端、前端、Python 后端和数据分析岗位。

### 15.3 MVP 首批技能

~~~

FastAPI
RAG
LangGraph

Docker

~~~

每个技能先支持少量清晰的升级阶段，例如 RAG 1→2、RAG 2→3、LangGraph 0→1、FastAPI 2→3。每个阶段固定五个能力单元，具体主观题和追问根据岗位画像、用户回答和当前短板动态生成。

## 十七、产品差异化

### 17.1 和 AI 简历工具的区别

普通 AI 简历工具主要是帮用户改文本。

本平台不是先改简历，而是先判断用户离目标岗位差什么，再通过关卡验证用户是否真的具备能力。

---

### 17.2 和学习平台的区别

普通学习平台是：

```text
看课 → 做题 → 完成课程
```

本平台是：

```text
岗位画像 → 能力差距 → 闯关题 → AI 批改 → 画像升级 → 匹配度提升
```

---

### 17.3 和刷题平台的区别

普通刷题平台只告诉用户对错。

本平台会进一步：

```text
1. 分析错因
2. 定位能力短板
3. 生成补强题
4. 判断是否升级用户画像
5. 重新计算岗位匹配度
```

---

## 十八、最终产品表达

可以这样对外描述：

> 这是一个岗位画像驱动的 AI 能力闯关平台。用户选择目标岗位后，平台会根据简历生成用户画像，识别用户与岗位要求之间的能力差距，并通过一关一关的 AI 出题、单题批改、错因分析和补强训练，帮助用户逐步提升技能等级。只有通过对应等级的全部关键关卡，用户画像才会升级，岗位匹配度也会随之提升。

更短的表达：

> 不是告诉你该学什么，而是通过一道道岗位能力关卡，帮你证明自己达到了目标岗位要求。

---

## 十九、核心总结

平台最终闭环是：

~~~
岗位画像定义目标
简历画像提供初始证据
Agent 交互校准用户能力
用户能力画像定义现状
全部未达标技能进入逐级评估
主观面试题验证下一等级能力
单题评分、追问与补强
五个能力单元全部通过则升级
画像升级后重新计算匹配度
直到达到岗位能力要求
~~~

这套方案的核心竞争力在于：

~~~
1. 目标明确：所有评估都服务于目标岗位画像
2. 能力可验证：简历不是结论，主观回答和追问形成有效证据
3. 评估自适应：题目和补强基于用户当前回答动态生成
4. 升级可量化：五个能力单元全部通过才允许技能升级
5. 求职强相关：题目、能力差距和岗位匹配度始终围绕同一目标岗位
~~~
