# 用户岗位画像生成方案

## 1. 方案目标

第一版实现用户通过平台提交一段岗位相关文本，由岗位画像生成 Agent 自动提炼岗位画像，并将合法结果保存到 `job_market_profiles`。

第一版只处理用户临时画像，暂不处理系统正式画像、岗位方向字典、平台岗位自动选样和画像版本管理。

核心链路：

```text
user_id + job_text
        ↓
输入校验与文本清理
        ↓
调用岗位画像生成 Agent
        ↓
Agent 输出规定格式的 JSON
        ↓
Pydantic 结构与业务规则校验
        ↓
编排层补充系统字段
        ↓
写入 job_market_profiles
        ↓
返回完整岗位画像
```

## 2. 核心原则

### 2.1 Agent 只根据用户材料生成

Agent 只能根据用户提交的 `job_text` 提炼岗位画像。

必须遵守：

- 所有画像结论必须能够从 `job_text` 中找到依据。
- 不使用模型常识补充用户未提供的信息。
- 不推测学历、经验、证书、技能等级或岗位职责。
- 输入中缺少的信息返回 `null` 或空数组。
- 即使材料不完整，也根据已有内容生成部分岗位画像。

### 2.2 Agent 负责内容，编排层负责保存

Agent 只生成岗位画像业务字段，不直接调用数据库工具。

编排层负责：

- 校验请求参数。
- 清理岗位文本。
- 调用能力层 Agent。
- 校验 Agent JSON。
- 补充 `user_id` 和 `profile_type`。
- 写入数据库。
- 处理事务和异常。

### 2.3 岗位名称必须生成

`job_name` 是唯一必须由 Agent 生成且不能为空的画像业务字段。

如果岗位材料没有明确岗位名称，Agent 应综合职责、技能和工作内容，提炼最贴切的岗位名称。

只有在完全无法判断岗位类型时，才允许返回：

```text
未明确岗位
```

## 3. 接口设计

### 3.1 接口路径

```http
POST /job/profiles/generate
```

### 3.2 请求参数

```json
{
  "user_id": "10001",
  "job_text": "用户粘贴的岗位名称、岗位职责、技能要求、学历和经验要求等信息",
  "use_system_job_data": false
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `user_id` | string | 是 | Java 层传入的用户 ID。 |
| `job_text` | string | 是 | 用户提交的任意岗位相关文本。 |
| `use_system_job_data` | boolean | 否 | 是否同时参考平台已有岗位数据；默认 `false`，第一版暂未启用。 |

调用方不需要传入：

- `profile_type`
- `job_name`
- `conversation_id`
- `direction_id`
- 数据库字段

编排层固定设置：

```text
profile_type = temporary
```

### 3.3 请求 Schema

```python
from pydantic import BaseModel, Field, field_validator


class TemporaryJobProfileGenerateRequest(BaseModel):
    """用户临时岗位画像生成请求。"""

    user_id: str = Field(min_length=1, max_length=100)
    job_text: str = Field(min_length=1, max_length=50000)
    use_system_job_data: bool = Field(
        default=False,
        description="是否同时参考平台已有岗位数据；第一版暂未启用",
    )

    @field_validator("user_id", "job_text")
    @classmethod
    def strip_text(cls, value: str) -> str:
        """清理请求文本首尾空白，并禁止纯空白内容。"""
        cleaned_value = value.strip()
        if not cleaned_value:
            raise ValueError("字段不能为空")
        return cleaned_value
```

### 3.4 系统岗位数据开关

`use_system_job_data` 用于预留“参考平台已有岗位数据”的能力。

当前版本规则：

```text
use_system_job_data = false
仅根据用户提供的 job_text 生成岗位画像。

use_system_job_data = true
当前版本不支持，接口明确返回功能未开放错误。
```

第一版不应静默忽略 `true`。如果调用方传入 `true`，应返回：

```json
{
  "code": 400,
  "msg": "参考系统岗位数据功能暂未开放",
  "data": null
}
```

对应业务检查：

```python
if request.use_system_job_data:
    raise BusinessException(
        code=400,
        msg="参考系统岗位数据功能暂未开放",
    )
```

未来启用后的预期流程：

```text
用户 job_text
    ↓
提炼岗位检索关键词
    ↓
从 job_raw_records 查询相关系统岗位样本
    ↓
用户材料 + 系统岗位样本
    ↓
岗位画像生成 Agent
```

未来启用时必须遵守：

- 用户提交的 `job_text` 是主要依据。
- 系统岗位数据只作为补充参考。
- 系统数据不能覆盖用户材料中的明确内容。
- 系统数据与用户材料冲突时，应优先采用用户材料。
- 需要明确限制系统样本数量和文本总长度。
- 需要记录是否实际使用了系统岗位数据，但该信息不写入岗位画像内容字段。

## 4. 输入处理

接口收到请求后先执行确定性处理，不立即调用模型。

### 4.1 用户 ID 校验

- 必须存在。
- 去除首尾空格。
- 最大长度为 100。
- Python 层不校验用户是否真实存在。
- 用户身份和访问权限由 Java 层负责。

### 4.2 岗位文本校验

- 必须存在。
- 不能是纯空格。
- 最大长度建议为 50000 字符。
- 不要求最少 50 字符。
- 不要求固定格式。
- 不要求必须出现岗位名称、职责或技能。

用户可以提交：

- 一条完整招聘信息。
- 多条招聘信息拼接文本。
- 岗位名称和岗位要求。
- 只有技能要求的岗位片段。
- 从招聘网站复制的混合文本。

### 4.3 文本清理

编排层建议执行：

- 去除首尾空格。
- 合并过多空行。
- 去除明显重复段落。
- 保留岗位名称、职责、技能、学历、经验和证书信息。
- 不在编排层尝试推测缺失内容。

清理后的文本保存于工作流状态：

```text
cleaned_job_text
```

## 5. Agent 调用设计

### 5.1 调用能力层

编排层通过 HTTP 调用：

```http
POST /agent/run
```

建议请求：

```json
{
  "query": "请根据以下岗位材料生成岗位画像：\n\n{cleaned_job_text}",
  "system_prompt": "岗位画像生成系统提示词",
  "tools": [],
  "inputs": {},
  "optional_features": {
    "conversation_context_enabled": false,
    "checkpoint_enabled": true,
    "long_term_memory_enabled": false,
    "deferred_tool_filter_enabled": false
  },
  "runtime_options": {
    "temperature": 0.1,
    "timeout_seconds": 60,
    "max_retries": 2
  }
}
```

### 5.2 Agent 运行约束

本次生成属于独立任务：

- 不读取用户历史会话。
- 不使用长期记忆。
- 不需要数据库写入工具。
- 不需要爬虫工具。
- 不需要岗位方向工具。
- 可以启用 Checkpoint 保存本轮 Agent 执行状态。

### 5.3 Agent 系统提示词核心规则

系统提示词必须包含：

```text
你是岗位画像提炼 Agent。

你只能根据用户提供的岗位材料生成画像，不得使用外部知识补充。
输入中没有明确依据的内容必须返回 null 或空数组。
不得推测学历、经验、证书、技能等级或岗位职责。

job_name 必须生成。
如果材料中没有明确岗位名称，请根据职责、技能和工作内容提炼最贴切的岗位名称。
如果完全无法判断，job_name 返回“未明确岗位”。

只输出符合规定结构的 JSON，不输出解释、Markdown 或额外文本。
```

## 6. Agent 输出结构

### 6.1 岗位职责

```python
class JobResponsibility(BaseModel):
    """岗位职责结构。"""

    name: str | None = None
    description: str | None = None
```

### 6.2 必备技能

```python
from typing import Literal


class RequiredSkill(BaseModel):
    """岗位必备技能结构。"""

    name: str
    category: str | None = None
    level: Literal[
        "了解",
        "熟悉",
        "熟练掌握",
        "能够独立应用",
    ] | None = None
    requirement: str | None = None
    knowledge_points: list[str] = Field(default_factory=list)
    tools: list[str] = Field(default_factory=list)
```

### 6.3 加分技能

```python
class PreferredSkill(BaseModel):
    """岗位加分技能结构。"""

    name: str
    category: str | None = None
    requirement: str | None = None
    tools: list[str] = Field(default_factory=list)
```

### 6.4 完整画像

```python
class GeneratedJobProfile(BaseModel):
    """Agent 根据用户岗位材料生成的岗位画像。"""

    job_name: str
    job_overview: str | None = None

    responsibilities: list[JobResponsibility] = Field(default_factory=list)
    required_skills: list[RequiredSkill] = Field(default_factory=list)
    preferred_skills: list[PreferredSkill] = Field(default_factory=list)

    education_requirement: str | None = None
    experience_requirement: str | None = None
    certificate_requirement: str | None = None
```

## 7. 空值约定

### 7.1 文本字段

缺失时返回 `null`：

```json
{
  "job_overview": null,
  "education_requirement": null,
  "experience_requirement": null,
  "certificate_requirement": null
}
```

### 7.2 列表字段

缺失时返回空数组：

```json
{
  "responsibilities": [],
  "required_skills": [],
  "preferred_skills": []
}
```

### 7.3 技能子字段

没有依据时返回 `null` 或空数组：

```json
{
  "name": "Python",
  "category": null,
  "level": null,
  "requirement": null,
  "knowledge_points": [],
  "tools": []
}
```

## 9. 输出校验

Agent 返回后执行：

```text
提取 JSON
    ↓
GeneratedJobProfile.model_validate()
    ↓
业务规则校验
```

### 9.1 结构校验

- 必须是合法 JSON。
- 只能包含规定字段。
- `job_name` 必须存在且不能为空。
- 列表字段必须是数组。
- 技能等级必须属于固定枚举或为 `null`。
- 技能名称必须存在。

### 9.2 业务校验

- `job_name` 去除首尾空格后不能为空。
- 列表中删除完全空白的职责项。
- 必备技能名称不能重复。
- 加分技能名称不能重复。
- 同一个技能不应同时存在于必备技能和加分技能。
- 不要求必须生成职责或技能。

建议数量限制：

```text
responsibilities：最多 15 项
required_skills：最多 30 项
preferred_skills：最多 20 项
knowledge_points：每项最多 20 个
tools：每项最多 20 个
```

## 10. 校验失败处理

### 10.1 JSON 格式错误

第一次输出无法解析时：

```text
将原始输出和校验错误交给模型修复
    ↓
重新校验一次
```

最多修复一次。

### 10.2 修复后仍失败

不写数据库，返回：

```json
{
  "code": 422,
  "msg": "岗位画像生成结果格式不正确",
  "data": null
}
```

### 10.3 材料信息较少

材料较少不是生成失败条件。

只要能提炼岗位名称，就允许生成部分画像，缺失字段保持为空。

## 11. 数据库保存

Agent 输出校验成功后，编排层补充：

```text
user_id = 请求中的 user_id
profile_type = temporary
```

保存示例：

```python
profile = JobMarketProfile(
    user_id=request.user_id,
    profile_type="temporary",
    job_name=generated.job_name,
    job_overview=generated.job_overview,
    responsibilities=[
        item.model_dump()
        for item in generated.responsibilities
    ],
    required_skills=[
        item.model_dump()
        for item in generated.required_skills
    ],
    preferred_skills=[
        item.model_dump()
        for item in generated.preferred_skills
    ],
    education_requirement=generated.education_requirement,
    experience_requirement=generated.experience_requirement,
    certificate_requirement=generated.certificate_requirement,
)
```

保存规则：

- 每次用户生成都新增一条临时画像。
- 不覆盖其他临时画像。
- 数据库异常时回滚。
- 数据库保存失败时不能返回生成成功。

## 13. 工作流设计

第一版建议使用以下节点：

```text
validate_input
    ↓
prepare_prompt
    ↓
generate_profile
    ↓
validate_output
    ↓
repair_output（按需）
    ↓
save_profile
    ↓
END
```

工作流状态：

```python
class TemporaryJobProfileState(TypedDict):
    """用户临时岗位画像生成流程状态。"""

    user_id: str
    job_text: str
    use_system_job_data: bool
    cleaned_job_text: str

    raw_agent_output: str | None
    generated_profile: dict | None
    validation_errors: list[str]
    retry_count: int

    saved_profile_id: int | None
```

## 14. 代码职责

```text
job_profile_api.py
    接收请求、依赖注入、统一响应

job_profile_service.py
    启动岗位画像生成流程

workflows/job_profile/
    控制生成、校验、修复和保存节点

capability_agent_client.py
    调用 capability-backend /agent/run

schemas/job_profile.py
    定义请求、Agent 输出和工作流数据结构

job_repository.py
    负责 job_market_profiles 数据库读写
```

## 15. 第一版暂不实现

- 系统正式岗位画像。
- `job_directions` 岗位方向字典关联。
- 参考系统已有岗位数据生成画像。
- 文件上传和 PDF、Word 解析。
- 平台岗位库自动选样。
- 多 Agent 协作。
- Agent 数据库写入工具。
- 画像审核和发布。
- 画像历史版本。
- 临时画像自动过期。
- 来源岗位和模型调用追踪。

## 16. 最终职责边界

```text
用户
  提供 user_id、job_text 和系统岗位数据参考开关

Agent
  只根据 job_text 提炼岗位画像 JSON

编排层
  校验输入、调用 Agent、校验 JSON、补充系统字段、保存数据库

数据库
  保存最终合法的临时岗位画像
```
