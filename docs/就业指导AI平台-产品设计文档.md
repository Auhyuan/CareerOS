# 就业指导 AI 平台 — 产品设计文档

> 版本 v1.0 | 状态：概念设计阶段

---

## 一、产品概述

### 1.1 产品定位

一个以 **数据驱动 + AI Agent** 为核心的就业指导平台。区别于市面上泛泛的"AI简历优化"工具，本平台基于**真实、持续更新的招聘市场数据**，为用户提供从现状分析、差距识别、学习成长到求职准备的全链路陪伴式服务。

### 1.2 核心价值

- **数据驱动**：所有分析和建议基于从真实招聘平台采集的岗位数据，而非 AI 凭空生成
- **全程陪伴**：不只是一次性分析工具，而是覆盖"分析 → 学习 → 成长 → 求职"完整闭环的成长平台
- **可执行**：学习计划有具体资源、时间节点、作业验收，不是泛泛的"学习 XXX 技术"

### 1.3 目标用户

| 用户群体 | 核心诉求 |
|---|---|
| 应届毕业生 | 不知道找什么方向，简历空白，缺乏求职经验 |
| 在校学生（大二/大三） | 提前了解市场要求，规划学习路径 |
| 职场转行人群 | 评估转行可行性，了解技能差距 |
| 在职提升人群 | 对标更高级岗位，明确提升方向 |

## 二、产品架构

整体分为四层，数据从上往下流转，学习结果向上反馈形成闭环。

```
┌─────────────────────────────────────┐
│           数据采集层                  │  定期脚本，后台运行
├─────────────────────────────────────┤
│           岗位库                      │  可独立浏览，不依赖 Agent
├─────────────────────────────────────┤
│         Agent 分析层                  │  多轮交互，核心功能
├─────────────────────────────────────┤
│           学习平台                    │  成长闭环，提升留存
└──────────────────┬──────────────────┘
                   │ 闭环反馈（学完重新评估）
                   ↑_______________________↑
```

## 三、功能模块详解

### 3.1 数据采集层

#### 采集策略

采用**方案一（离线预处理）**：定期后台脚本采集，而非 Agent 实时爬取。

理由：
- 用户对话时不能等待爬虫，体验差
- 招聘需求变化不快，每周/每天更新完全够用
- 稳定性更高，不受目标网站实时状态影响

#### 采集来源

- Boss 直聘
- 拉勾网
- 猎聘
- 后续可扩展其他平台

#### 处理流程

```
原始 JD 抓取 → 大模型结构化提取 → 写入 PostgreSQL 数据库
```

大模型从原始 JD 中提取以下结构化字段：

| 字段 | 说明 |
|---|---|
| 岗位名称 | 标准化后的岗位分类 |
| 公司名称 | 招聘方 |
| 薪资范围 | 最低 ~ 最高（K） |
| 必备技能 | 硬性要求的技术栈 |
| 加分技能 | 优先条件 |
| 工作年限要求 | 经验要求 |
| 学历要求 | 最低学历 |
| 公司规模 | 初创 / 中型 / 大厂 |
| 发布时间 | 原始发布日期 |
| 最后采集时间 | 本平台最后一次抓到该条数据的时间 |
| 数据状态 | 招聘中 / 可能已关闭 / 已确认关闭 |

#### 数据时效管理

仅靠"发布时间"不够，需要结合"最后采集时间"判断职位是否仍在招聘：

```
招聘中      → 最近一次采集仍存在
可能已关闭  → 超过 N 天未被采集到
已确认关闭  → 招聘平台明确标记关闭
```

展示时标注数据采集时间，保护平台信誉，给用户清晰的时效预期。

#### 数据存储

使用 **PostgreSQL** 存储，结构化字段满足精确查询（薪资范围、学历、地点等过滤条件）。

### 3.2 岗位库

岗位库是平台的**独立入口**，用户无需上传简历即可浏览，扩大使用门槛。

#### 两个数据层次

**岗位聚合层**（大模型整理后的市场分析）

```
前端开发
├── 市场平均薪资：15K ~ 40K
├── 需求热度：⭐⭐⭐⭐⭐
├── 必备技能：HTML / CSS / JavaScript / Vue / React
├── 加分技能：TypeScript / Node.js / 性能优化
├── 学历要求分布：本科 70% / 专科 20% / 硕士 10%
├── 经验要求分布：1-3年 50% / 3-5年 35% / 应届 15%
└── 职业发展路径：初级前端 → 高级前端 → 前端架构师 → 技术总监
```

**职位原始层**（具体在招信息）

```
字节跳动 - 前端开发工程师
├── 薪资：25K ~ 35K
├── 要求：3年以上 / 本科 / React + TypeScript
├── 发布时间：2026-05-20
└── 状态：招聘中（采集时间：2026-06-05）
```

#### 岗位颗粒度设计

采用**两级选择**：先选大类，再选细分方向。

```
后端开发
├── Java 方向
├── Go 方向
├── Python 方向
└── Node.js 方向
```

#### 市场趋势（数据积累后上线）

基于持续采集的历史数据，展示：
- 某技能需求热度变化趋势
- 某岗位平均薪资走势
- 某岗位供需比变化

这是平台独有的数据资产，竞品无法复制。

### 3.3 Agent 分析层

Agent 是平台核心，基于 **LangGraph** 构建多节点状态机，支持与用户多轮交互。

#### Agent 整体流程

```
用户上传简历（或填写技能问卷）
           ↓
      简历解析节点  →  结构化用户画像
           ↓
      岗位匹配节点  →  从岗位库查询（用户已选定岗位）
           ↓
      差距分析节点  →  技能 Gap + 匹配度评分
           ↓
      多轮对话节点  ←→  用户追问 / 调整需求
           ↓
      计划生成节点  →  个性化学习计划 + 职业路径
```

#### 状态管理

```python
class AgentState(TypedDict):
    resume_profile: dict      # 解析后的用户画像
    target_job: str           # 目标岗位（从岗位库选择）
    job_requirements: dict    # 岗位要求
    gap_analysis: dict        # 技能差距分析
    learning_plan: dict       # 当前版本学习计划
    messages: list            # 对话历史
    current_step: str         # 当前所处阶段
```

#### 核心 Tools

| Tool | 作用 |
|---|---|
| `parse_resume` | 解析简历，提取技能 / 经验 / 学历 |
| `query_job_requirements` | 从岗位库查询岗位要求（按 ID 精确查询） |
| `gap_analysis` | 对比简历 vs 岗位要求，输出差距报告 |
| `match_companies` | 推荐具体在招的匹配公司 |
| `generate_learning_plan` | 生成结构化学习计划 |
| `optimize_resume` | 针对目标岗位优化简历内容 |
| `generate_interview_questions` | 生成岗位高频面试题 |
| `query_career_path` | 查询职业发展路径 |

#### 多轮交互场景

用户可以在对话中动态调整，Agent 路由到对应节点：

| 用户说 | Agent 动作 |
|---|---|
| "我只有 3 个月时间" | 重新生成压缩版计划 |
| "我不想学 Java" | 推荐其他细分方向 |
| "详细说说 Kubernetes 怎么学" | 展开某个知识点 |
| "帮我优化一下简历" | 触发简历优化节点 |
| "给我出一些面试题" | 触发面试准备节点 |

#### 差距分析输出示例

```
匹配度：62%

✅ 已掌握（8 项）
   HTML / CSS / JavaScript / Vue / Git / ...

❌ 必备缺口（3 项）
   TypeScript（该岗位 85% 要求）
   React（该岗位 70% 要求）
   前端工程化 / Webpack（该岗位 60% 要求）

⚡ 加分项缺口（2 项）
   Node.js 基础
   性能优化经验

📋 匹配公司（基于当前简历）
   ├── 完全匹配：中小型公司初级岗位（3 家在招）
   └── 提升后可匹配：字节跳动 / 腾讯初级岗位
```

#### 用户没有简历的处理

提供**技能自测问卷**代替简历上传，降低使用门槛：

```
问卷内容：
- 编程语言掌握情况（自评 1-5 分）
- 做过哪些类型的项目
- 工作/实习年限
- 学历情况
- 是否有开源项目 / GitHub
```

### 3.4 学习平台

学习平台是产品**留存的关键**，将一次性工具变成持续陪伴的成长平台。

#### 学习计划看板

Agent 生成的计划可视化呈现，而非纯文字：

```
目标岗位：高级前端开发工程师
总周期：16 周    当前进度：第 4 周    完成度：25%

第一阶段（1-4 周）TypeScript 基础        ██████░░░░  完成
第二阶段（5-8 周）React 深入              ░░░░░░░░░░  未开始
第三阶段（9-12 周）前端工程化              ░░░░░░░░░░  未开始
第四阶段（13-16 周）项目实战 + 面试准备    ░░░░░░░░░░  未开始
```

每个阶段细分为若干学习任务，每个任务包含：
- 知识点说明
- 推荐学习资源（B 站 / MDN / 书籍 / 官方文档）
- 对应作业

#### 作业系统

支持多种作业类型，AI 采用不同批改策略：

| 作业类型 | 提交方式 | AI 批改方式 |
|---|---|---|
| 代码题 | 直接粘贴代码 | 运行验证 + 逻辑审查 + 优化建议 |
| 问答题 | 文字回答 | 语义评估理解深度 |
| 项目作业 | GitHub 链接 | 代码结构 / 规范 / 实现思路审查 |
| 读书笔记 | 文字总结 | 评估关键点掌握情况 |

**AI 批改质量标准**（避免泛泛）：

```
❌ 不好的批改：
"你的代码有错误，请修改"

✅ 好的批改：
"你的异步处理思路正确，但第 12 行没有处理 reject 情况，
 这在生产环境中会导致未捕获的 Promise 异常。
 建议改为：try-catch 包裹 + .catch() 兜底。
 另外第 8 行的变量命名 'a' 建议改得更有语义，
 例如 'userList'，这是代码可读性的基本要求。"
```

#### 打卡与学习记录

- 连续打卡天数
- 每日学习时长记录
- 各阶段完成情况
- 薄弱知识点标记

#### 第三方学习资源聚合

不自建内容，直接聚合外部优质资源，成本极低：

```
TypeScript 基础
├── 📺 推荐视频：TypeScript 入门到精通 - B站
├── 📖 推荐文档：TypeScript 官方 Handbook
├── 🧪 推荐练习：TypeScript Exercises（在线练习网站）
└── 📚 推荐书籍：《TypeScript 编程》- O'Reilly
```

#### Agent 与学习平台的联动

这是产品最核心的差异化设计：

```
用户学习一段时间后
        ↓
Agent 主动分析学习数据：
"你在 TypeScript 泛型上连续卡了两周，这是高频面试考点。
 建议调整策略：先跳过复杂泛型，完成后续章节后再回来攻克。"
        ↓
用户完成全部计划后
        ↓
Agent 重新评估匹配度：
"你现在的匹配度已从 62% 提升至 88%。
 建议开始准备这 3 家公司的面试，
 同时建议更新简历中的技能部分。"
```

## 四、技术选型建议

| 层次 | 技术方案 | 说明 |
|---|---|---|
| Agent 框架 | LangGraph | 多节点状态机，支持多轮交互 |
| 可观测性 | LangSmith | Prompt 调试和优化 |
| 数据库 | PostgreSQL | 结构化岗位数据存储 |
| 简历解析 | 大模型 + PDF/Word 解析库 | 兼容多种格式 |
| 后台任务 | 定时脚本（Celery / Cron） | 定期数据采集 |
| 前端框架 | 根据团队技术栈自定 | — |

## 五、上线优先级规划

### Phase 1 — MVP（核心验证）

目标：跑通主流程，验证 AI 分析质量

- 岗位库浏览（手动整理 50-100 条数据，先不做爬虫）
- 简历上传 + 岗位选择
- 差距分析 + 学习计划生成
- 基础多轮对话
- 技能自测问卷（替代简历上传）

### Phase 2 — 成长闭环

目标：提升用户留存，形成回访习惯

- 学习计划看板可视化
- 作业提交 + AI 批改
- 打卡记录 + 学习进度追踪
- 简历优化功能
- 岗位收藏与对比

### Phase 3 — 差异化亮点

目标：建立竞品难以复制的护城河

- 市场趋势分析（基于历史采集数据）
- 面试准备（高频题 + AI 点评回答）
- 学习完成后重新评估 + 闭环反馈
- 职业路径知识图谱
