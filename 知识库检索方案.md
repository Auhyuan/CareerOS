## 二、核心设计：延迟返回模式

### 2.1 为什么不用直接返回？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **直接返回** | Agent 一次调用完成 | 检索内容可能很大，ToolMessage 会很长 |
| **延迟返回（推荐）** | 统一格式、可加引用规则、token 优化 | Agent 需要两轮调用 |

### 2.2 Command 机制

LangGraph 的 `Command` 对象实现延迟返回：

```python
from langgraph.types import Command

@tool
async def retrieve_knowledgebase_chunks(query: str, runtime: ToolRuntime) -> Command | dict:
    # 执行检索
    kb_results = await KbUtils.retrieve_knowledgebase(...)

    # 返回 Command，自动更新 state 并进入下一轮
    return Command(
        update={
            "messages": [ToolMessage(content="工具调用完成", tool_call_id=runtime.tool_call_id)],
            "retrieval_context": kb_results.get("context_str"),
            "reference_map": kb_results.get("reference_map"),
        }
    )
```

**Command 的语义**：
1. 把 `update` 里的内容**合并到 state**
2. **自动触发下一轮模型调用**
3. 不返回给用户，直接继续执行

## 三、检索工具分类

### 3.1 工具清单

| 工具名 | 用途 | 使用场景 |
|--------|------|----------|
| `retrieve_knowledgebase_chunks` | 片段检索 | 查找原文段落、引用 |
| `retrieve_knowledgebase_wiki` | Wiki 检索 | 查业务知识、规定、流程 |
| `retrieve_knowledgebase_full_content` | 全文检索 | 总结特定文档 |
| `retrieve_attachment_chunks` | 附件片段检索 | 查用户上传的附件 |
| `retrieve_attachment_full_content` | 附件全文检索 | 总结用户上传的附件 |

### 3.2 工具定义

```python
def get_knowledgebase_tools(kb_config: KnowledgeConfig = None) -> list[Tool]:
    """
    获取知识库相关工具
    kb_config: 知识库配置，包含 kb_ids 和 kb_doc_ids
    """

    @tool
    async def retrieve_knowledgebase_chunks(query: str, runtime: ToolRuntime) -> Command | dict:
        """
        在知识库中进行非指定文档的常规检索。
        当需要查找原始文档段落、引用原文时使用。

        Args:
            query: 检索问题，优先使用完整语义查询句
        """
        ...

    @tool
    async def retrieve_knowledgebase_wiki(query: str, runtime: ToolRuntime) -> Command | dict:
        """
        在知识库中检索 Wiki。
        当用户询问业务知识、规定或流程时使用。
        """
        ...

    @tool
    async def retrieve_knowledgebase_full_content(target_document: str, runtime: ToolRuntime) -> Command | dict:
        """
        获取指定文档的全文总结内容。
        当用户明确要求总结某个文档时使用。
        """
        ...

    return [
        retrieve_knowledgebase_full_content,
        retrieve_knowledgebase_chunks,
        retrieve_knowledgebase_wiki
    ]
```

## 四、检索流程（KbUtils）

### 4.1 入口方法

```python
class KbUtils:
    """知识库工具类"""

    @staticmethod
    async def retrieve_knowledgebase(
        user_id: str,
        kb_ids: list[str],
        kb_doc_ids: list[str],
        query: str,
        start_idx: int = 1,
        existing_chunk_ids: set = None,
        top_k: int = 10,
        rerank_top_k: int = 5
    ) -> dict:
        """
        知识库片段检索主流程

        Args:
            user_id: 用户 ID
            kb_ids: 知识库 ID 列表
            kb_doc_ids: 指定文档 ID 列表
            query: 检索问题
            start_idx: 引用编号起始值
            existing_chunk_ids: 已有的 chunk_id（用于去重）
            top_k: 向量检索返回数量
            rerank_top_k: Rerank 后保留数量

        Returns:
            {
                "context_str": "检索到的上下文",
                "reference_map": { "1": {...}, "2": {...} },
                "filtered_chunk_ids": ["id1", "id2"]  # 被过滤的重复 ID
            }
        """
```

### 4.2 检索流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    retrieve_knowledgebase()                     │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  1. Milvus 向量检索                                             │
│                                                                 │
│  - Query embedding 模型生成 query 向量                           │
│  - Milvus ANN 查询，Top-K 候选                                  │
│  - 可指定 kb_doc_ids 限定文档范围                               │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  2. 过滤已有 chunk（跨轮去重）                                   │
│                                                                 │
│  - 剔除 existing_chunk_ids 中已有的 chunk                        │
│  - 避免同一会话中重复引用                                       │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  3. Rerank 重排                                                 │
│                                                                 │
│  - 使用 Rerank 模型对候选 chunk 重排                             │
│  - 保留 Top-K（如 5 条）                                        │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  4. 引用过滤                                                    │
│                                                                 │
│  - 引用数量检查（超出限制则分级过滤）                           │
│  - 按相关度排序，保留高相关度结果                                │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  5. 上下文组装                                                  │
│                                                                 │
│  - 组装 context_str（带引用编号）                                │
│  - 组装 reference_map（元数据映射）                              │
└─────────────────────────────────┬───────────────────────────────┘
                                  ↓
┌─────────────────────────────────────────────────────────────────┐
│  6. 返回结果                                                    │
│                                                                 │
│  return {                                                       │
│      "context_str": "...",                                       │
│      "reference_map": {...},                                     │
│      "filtered_chunk_ids": [...]  # 被过滤的重复 ID             │
│  }                                                             │
└─────────────────────────────────────────────────────────────────┘
```

## 五、引用机制

### 5.1 reference_map 结构

```python
reference_map = {
    "1": {
        "kb_id": "kb-001",
        "doc_id": "doc-001",
        "chunk_id": "chunk-001",
        "content": "检索到的文档内容...",
        "doc_name": "文档标题.pdf",
        "type": "chunk",  # chunk / wiki / attachment
        "url": "..."  # 可选的文档链接
    },
    "2": {
        "kb_id": "kb-001",
        "doc_id": "doc-002",
        "chunk_id": "chunk-002",
        "content": "另一段内容...",
        "doc_name": "另一文档.pdf",
        "type": "chunk"
    }
}
```

### 5.2 引用编号注入到 prompt

中间件根据 `reference_map` 生成引用标注：

```
<knowledge_instruct>
# 知识库获取的参考资料
[1] 文档标题.pdf
内容：检索到的文档内容...

[2] 另一文档.pdf
内容：另一段内容...

# 回答要求：
1. 如果引用了参考资料，必须加来源编号（如：苹果富含维生素C ⁽¹⁾）
2. 单句引用的资料数量尽量少
</knowledge_instruct>
```

## 六、中间件注入机制

### 6.1 中间件注册

在 Agent 创建时注册 `InjectKBPromptMiddleware`：

```python
middlewares = [
    ...
    InjectKBPromptMiddleware(ref_display=True),  # ⭐ 知识库注入
    ...
]
```

### 6.2 中间件实现

```python
class InjectKBPromptMiddleware(AgentMiddleware[RetrievalState]):

    state_schema = RetrievalState  # ⭐ 声明 state 结构

    async def awrap_model_call(self, request, handler):
        # 从 state 读取检索结果
        retrieval_context = request.state.get("retrieval_context", "")

        if not retrieval_context:
            return await handler(request)

        # 构建注入内容
        injected_prompt = f"""
<knowledge_instruct>

{retrieval_context}

# 回答要求：
1. 如果引用了参考资料，必须加来源编号...
</knowledge_instruct>
"""

        # 追加到 system prompt
        final_sys_prompt = f"{request.system_message.content}\n{injected_prompt}\n"
        return await handler(request.override(system_message=SystemMessage(content=final_sys_prompt)))
```

### 6.3 State 定义

```python
class RetrievalState(AgentState):
    retrieval_context: str = Field(
        description="知识库上下文，包含所有检索到的文档内容",
        default="",
    )
    reference_map: dict = Field(
        description="知识库引用映射表",
        default={},
    )
```

## 七、多轮检索合并

### 7.1 合并策略

同一轮内多次调用知识库工具，结果会合并：

```python
def _build_merged_retrieval_update(runtime, section_title, new_context, new_reference_map):
    """合并同一次 agent 运行内的检索结果"""
    old_context = runtime.state.get("retrieval_context", "")
    old_reference_map = runtime.state.get("reference_map", {})

    merged_context = f"{old_context}\n\n{section_title}\n{new_context}"
    merged_reference_map = {**old_reference_map, **new_reference_map}

    return {
        "messages": [ToolMessage(content="工具调用完成", ...)],
        "retrieval_context": merged_context,
        "reference_map": merged_reference_map,
    }
```

### 7.2 编号连续性

每次新增引用时，从 `len(reference_map) + 1` 开始编号，确保编号连续：

```python
reference_map = runtime.state.get("reference_map", {})
start_idx = len(reference_map) + 1  # ⭐ 接着前面的编号
```

## 九、错误处理

### 9.1 工具返回错误

```python
@tool
async def retrieve_knowledgebase_chunks(query: str, runtime: ToolRuntime) -> Command | dict:
    try:
        # 检索逻辑
        ...
    except Exception as e:
        logger.error(f"知识库检索失败: {e}")
        return {"error": str(e)}  # ⭐ 返回错误，不更新 state
```

### 9.2 错误信息给 Agent

```python
# 返回错误时，Agent 看到 ToolMessage({"error": "未检索到相关内容"})
# Agent 可以根据错误信息决定是否重试或其他操作
```

### 9.3 空结果处理

```python
if kb_results.get("context_str"):
    return Command(update={...})
elif kb_results.get("filtered_chunk_ids"):
    # 全部是重复内容，过滤掉了
    return {
        "success": True,
        "message": "工具调用成功，本次检索结果均为重复内容，已过滤。"
    }
else:
    return {"error": "知识库检索结果为空"}
```

## 十二、总结

| 特性 | 实现方式 |
|------|----------|
| **延迟返回** | LangGraph `Command` 对象 |
| **结果存储** | Agent `state.retrieval_context` |
| **Prompt 注入** | `InjectKBPromptMiddleware` |
| **引用编号** | `reference_map` + 上标格式 |
| **多轮合并** | `_build_merged_retrieval_update` |
| **跨轮去重** | `existing_chunk_ids` 参数 |
